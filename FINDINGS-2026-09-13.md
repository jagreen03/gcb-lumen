## The external AI's response, summarized

It recommended **SAX (a circuit-level S-parameter simulator) combined
with an assumed per-junction excess-loss value**, rather than trying
to extend `femwell` (a mode solver) to do full 3D component-level loss

as a scattering-matrix block, assigning it a default excess loss "e.g.
0.15 dB to 0.3 dB per 2:1 combiner junction, derived from standard

system-level number. It also referenced two specific file names —
`k16_tile.py` and `mmi_power_tree.py` — as "the layout geometry you
already built."

## What was actually built and run (not just discussed)

`sax_combiner_model.py` (new, this repo): a real SAX circuit model of
the exact `mmi_power_tree.py` binary-tree topology, parameterized by
an assumed per-junction excess loss, at both `N=8` and `N=16`.

**A real bug was found and fixed while building this — recorded, not
silently corrected.** The first version compared the tree's actual
combined output against an incorrectly-derived "ideal" reference
(treating N coherent inputs' amplitudes as simply additive, i.e.
ideal output amplitude = N). That's wrong: for N equal-amplitude,
in-phase inputs combining losslessly into **one** output port, energy
conservation requires ideal output *power* = N, so ideal output
*amplitude* = `sqrt(N)`. The bug manifested as a spurious extra
`~10*log10(N)` dB of "loss" — for N=8 it silently turned a real 0.3 dB
answer into a wrong 9.33 dB answer. Caught by hand-deriving the
3-stage cascade algebraically before trusting the script's number, not
by inspection alone.

**After the fix, the model reproduces the existing literature estimate
exactly:**

```
--- N=8 (Phase-I bench) ---
  assumed excess_loss/junction=0.10 dB -> 3 stages, total = 0.3000 dB (0.1000 dB/stage)
  assumed excess_loss/junction=0.30 dB -> 3 stages, total = 0.9000 dB (0.3000 dB/stage)
--- N=16 (Phase-II integrated array) ---
  assumed excess_loss/junction=0.10 dB -> 4 stages, total = 0.4000 dB (0.1000 dB/stage)
  assumed excess_loss/junction=0.30 dB -> 4 stages, total = 1.2000 dB (0.3000 dB/stage)
```

At the `0.1 dB/stage` literature-cited figure, this exactly matches
what `EXTERNAL_AI_BRIEFING.md`'s own hand-derivation already predicted
(0.3 dB for N=8, 0.4 dB for N=16) — a genuine, independent confirmation
that the cascade arithmetic is right, via real running code rather than
a hand-derivation alone.

## What this does and does not close

**Does not close the real open question.** `EXCESS_LOSS_DB` in
`sax_combiner_model.py` is still an assumed placeholder (0.1 and 0.3,
neither measured). The real per-junction loss for the actual fabricated
geometry is still unknown — this repo's core blocking question is
unchanged.

**Does close a real, smaller question**: is "SAX + assumed loss,
cascaded" a *workable* framework for this specific topology? Yes,
confirmed by building and running it, not merely by the external AI
asserting it. The moment a real per-junction number exists — from a
`femwell`-based extraction with an actual loss mechanism fed in, a
cited literature/vendor figure, or a bench measurement — plugging it
into `EXCESS_LOSS_DB_OPTIMISTIC`/`_UPPER` (or a new constant) in
`sax_combiner_model.py` immediately produces a real system-level
number for both N=8 and N=16, with zero further modeling work.
